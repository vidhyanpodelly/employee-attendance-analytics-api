Comprehensive review of the starter implementation in `app/main.py`.

| 1 | `compute_late_minutes` (lines 33–37) | Timezone naive/UTC mismatch when replacing hour/minute with IST shift start. Truncates seconds to minutes before checking `> 10`, so at 09:40:01 IST (601 seconds elapsed) it returns 0 instead of 10. Does not handle overnight shifts where shift started previous day. Does not truncate instants to whole seconds (R1). | Passing `09:40:01` IST against shift `09:30` returns `0` instead of `10`. Subtracting UTC punch-in from IST start produces a 5.5-hour skew. | Converted punch-in to IST, created shift start on calculated attendance date, checked `elapsed_seconds > 600` strictly, then took whole minutes floor. |
| 2 | `compute_work_hours` (lines 40–41) | Uses Python's built-in `round(..., 2)` which performs banker's rounding (round-half-to-even) and float approximation rather than Decimal half-up rounding (R4). Does not truncate instants to whole seconds. | An elapsed duration of 9018 seconds / 3600 = 2.505 hours returns `2.50` with built-in `round()`, but contract requires half-up rounding to `2.51`. | Truncated instants to whole seconds, then rounded via `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 3 | `compute_overtime` (lines 44–47) | Returns overtime minutes unconditionally without enforcing the minimum 30-minute threshold (R3). Querying by department returns `total` equal to entire collection count. Documents are unordered. | Set `skip = (page - 1) * page_size`, passed query filter `q` to `count_documents(q)`, added `.sort("emp_code", ASCENDING)`, and added validation `ge=1, le=100`. |
| 7 | `punch_in` (lines 99–122) | Missing employee existence check; accessing `emp["shift_start"]` on missing employee raises `TypeError` (500) instead of 404. Date calculated using OS local time rather than IST and overnight rules (R1). Check-then-insert race condition. Injects forbidden `"id"` field into response. Returns datetime objects instead of epoch milliseconds. Missing validation on `punched_at` and `status`. | Punch-in for unknown employee returns 500. Punch-in at 01:00 IST for overnight shift assigns wrong calendar date. ## Items Examined and Determined Not to Be Defects

1. **String representation for dates and shift times (`YYYY-MM-DD`, `HH:MM`):**
   Calendar dates and daily shift boundaries are intentionally stored as ISO-8601 strings rather than BSON datetimes. As detailed in `DATA_MODEL.md` section 1, a calendar date is not an instant in time; casting it to a datetime forces an arbitrary UTC/local time conversion. Keeping them as plain strings preserves timezone neutrality.

2. **Addressing records by natural composite keys `(emp_code, date)` rather than MongoDB `_id`:**
   The API contract intentionally conceals internal MongoDB `_id` ObjectIds from clients. Attendance records are addressed by their domain identity `(emp_code, date)` and employees by `emp_code`. This avoids leaky database abstractions.
